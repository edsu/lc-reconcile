lc-reconcile

Reconcile headings against a local index of id.loc.gov.

      Request and response
      

  
      
    
      Using the API
      
    
      This service speaks version 0.2 of the
      Reconciliation
      Service API, the protocol OpenRefine uses. Its endpoint is
      
    
      /reconcile
      
    
      To use it in OpenRefine, choose Reconcile → Start reconciling… → Add standard service…
      and give that URL. This page makes the same requests OpenRefine does; open
      Request and response above to see them.
      

    
      Endpoints
      
    
      
      
      RequestGives
      
      
      GET /reconcile
        The service manifest: name, types, and where the services below are.
      
      
      GET or POST /reconcile
      with queries      		
        Results for a batch of queries, keyed by query id; the manifest asks for 50 at a time. A POST is form-encoded,
          as OpenRefine sends it. Add callback for JSONP.
      
      
      GET /reconcile/suggest/entity
        Autocomplete: headings starting with prefix (two characters or more),
          optionally of one type, paged with cursor.
      
      
      GET /reconcile/suggest/type
      
        GET /reconcile/suggest/property      		
        Autocomplete for types and query properties.
      
      
      GET /reconcile/preview
        A small HTML card for the heading id, as shown beside the results above.
      
      
      GET /status
        What the index holds: each scheme's records, snapshot date and how far it has synced.
      
    
      

    
      A query
      
    
      {
  "q0": {
    "query": "Verne, Jules",
    "type": "PersonalName",
    "limit": 5,
    "properties": [{"pid": "dates", "v": "1828-1905"}]
  },
  "q1": {
    "query": "",
    "properties": [{"pid": "marc_key", "v": "650 0$aAeroplanes."}]
  }
}
      
    
      Send it as the queries parameter:
      
    
      
    
        
      
      • type is a MADS kind of heading, such as PersonalName,
        Topic, GenreForm or Medium. Without one, every kind is
        searched, and similar headings are mostly names.
        • 
      
      • marc_key gives the heading as a MARC field. It's compared subfield by subfield,
        relators and links are ignored, and its tag sets the type.
        • 
      
      • dates are added to a name heading that lacks them.
        • 
      
      • scheme chooses the LC schemes to search, separated by spaces. Without it, names,
        subjects and genre/form terms are searched; a marcKey's indicator or $2, or the
        Medium type, can choose another.
        • 
    
      

    
      A result
      
    
      Each candidate has an id (the authority's URI at id.loc.gov), a name,
      its type, a score from 0 to 100, match and a
      description of how it was found. Names also carry rwo, the URI of the
      person or body itself.
      
    
      match: true means the candidate can be accepted without review. It's given only
      to the one authorized heading of the type asked for whose normalized form equals the query, or
      failing that to the one heading with the query as an earlier established form (Aeroplanes
      for Airplanes). Variants, undifferentiated names, replacements for deprecated headings
      and similar headings are offered as candidates, and so is anything for a field that names another
      vocabulary (650 2, $2fast). Scores only put the candidates in order.
